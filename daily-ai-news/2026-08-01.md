## 1. 🔥 MVA: 李飞飞 & Yilun Du 联手——Masked Visual Actions 打通视频生成与机器人控制

- **来源**: Stanford / Harvard / UMD, 论文 arXiv:2607.19343, 2026-07-22（近两日在学术圈广泛传播）
- **作者**: Hadi Alzayer, Wenlong Huang, Haonan Chen, Christopher Luey, **Lvmin Zhang (ControlNet)**, Maneesh Agrawala, Gordon Wetzstein, **Li Fei-Fei**, **Yilun Du**, **Jiajun Wu**, Jia-Bin Huang
- **发生了什么**: 提出 **Masked Visual Actions (MVA)**，一种像素空间控制接口，将机器人动作表示为视频中实体的部分掩码轨迹。仅用 15 小时机器人数据对 Wan2.2 (14B) 做 LoRA 微调，同一 checkpoint 可同时作为前向世界模拟器（给定机器人运动→预测场景变化）和逆向动作生成器（给定目标物体运动→合成机器人行为）。最关键的是实现了**跨本体零样本泛化**：训练用单臂机器人数据，推理可直接用于未见过的双臂机器人。
- **值得关注的原因**:
  - **研究范式层面的挑战**：这篇工作直接质疑"具身智能是否需要专属大模型"这一基本假设。通过 URDF 运动学作为中转层，用逆运动学 (IK) 将模型输出的"末端轨迹"适配不同本体，彻底绕开了传统 VLA（视觉-语言-动作）模型输出关节角导致的本体耦合问题。
  - **视频+具身的最大公约数**：这是近年来最具影响力的"视频理解/生成模型 × 机器人操控"交叉工作之一，也是李飞飞（空间智能路线）与 Yilun Du（隐空间世界模型路线）首次在学术立场上的"合流"。在 RoboCasa 任务中，MVA 辅助规划带来 7~26pp 成功率提升；策略评估与真实执行的相关系数达 0.982。
  - **产业意义**：模型零成本借用开源视频生成模型 Wan2.2 + 极少量机器人数据，打破了从头训练基座模型的高门槛，对创业公司和学术界都是极大的吸引力。
- **技术启发**: "最好的翻译不是逼对方学你的语言，而是用对方听得懂的话说你想说的事。"——在视频分析领域，与其设计一套全新的动作表征让视频模型重新学习，不如思考如何将你的输出空间"说成"视频模型已经在预训练中理解的形式（像素轨迹 / 视觉 token）。

- **链接**: [arXiv:2607.19343](https://arxiv.org/abs/2607.19343) | [项目主页 (含 Demo)](https://masked-visual-actions.github.io/)

## 2. 🧠 PhiZero: 基于"物理语言"的世界模型——让 AI 先推理物理规律，再生成视频

- **来源**: 中科院自动化所 (CASIA) 模式识别国家重点实验室, arXiv:2607.28624, HuggingFace 7/31 高票热门
- **作者**: Shuyao Shang, Yuqi Wang, Ruopeng Gao, Xu Chen, Tieniu Tan, Lue Fan, Zhaoxiang Zhang
- **发生了什么**: 提出 **Physical Language（物理语言）**——一种从无标签野外视频中自监督学习得到的紧凑离散状态转移表示。PhiZero 采用 **Reason-then-Render** 新范式：先用自回归 VLM（基于 Qwen3-VL-4B）将当前视觉状态+动作意图推理为物理语言序列，再通过扩散解码器渲染成未来视频。物理语言扮演着从"像素预测"到"显式物理推理"的中间桥梁角色。
- **值得关注的原因**:
  - **从隐式到显式的范式升级**：传统世界模型直接在像素空间预测未来帧，物理规律隐含在高维视觉表征中，容易产生物理不一致性。PhiZero 通过离散化的物理语言显式建模世界状态转移，在 Physics-IQ (41.2)、PhyGround (3.01)、WorldModelBench (4.88)、IntPhys2 (56.34) 四项物理基准上全面超越 Sora 2、Cosmos3、Wan2.2 等闭源和开源模型。
  - **连接视频理解与物理推理**：物理语言 tokenizer (Physical Language Tokenizer) 的设计——用 transition-level Q-Former 从相邻隐空间状态提取有序特征，再通过 FSQ 离散化——为"如何从视频中提取结构化物理知识"提供了可操作的方案。
  - **对具身智能的潜在价值**：如果物理语言能可靠地表征"推→滚""碰→倒"等物理因果，它可以直接作为机器人策略的世界先验，减少对昂贵实机交互数据的依赖。
- **技术启发**: 当前视频模型大多停留在"像素→像素"的端到端路径，PhiZero 的"reason-then-render"思路暗示着一个更有前途的方向——在视频理解和生成之间插入一个**可解释的离散中间状态**。这个中间状态本身也是一个值得探索的研究空白：如何设计 tokenizer、如何评价物理语言的质量、是否可以迁移到机器人操控场景。

- **链接**: [arXiv:2607.28624](https://arxiv.org/abs/2607.28624) | [项目主页](https://phi-zero.github.io/) | [GitHub](https://github.com/yaoyao-jpg/PhiZero)

## 3. 🤖 Qwen-UI-Agent: 真实世界基础 GUI Agent——从"会聊天"到"会操作"

- **来源**: 阿里通义团队, arXiv:2607.28227, HuggingFace 7/31 最高票论文
- **作者**: Hanzhang Zhou, Panrong Tong, Xu Zhang, Quyu Kong 等
- **发生了什么**: 发布 Qwen-UI-Agent，一个面向**真实设备运行时**的基础 GUI Agent。核心创新：(1) 搭建了 100+ 台真实手机的运行环境，覆盖 150+ 应用；(2) **统一动作空间**——GUI 操作 + CLI 命令行 + 批处理动作在一次推理中协同；(3) 在线 RL 支持超 100 步的长时程轨迹训练，10000+ 并发环境加速；(4) **AutoResearch 数据飞轮**——Agent 自动构建任务、诊断失败、规划下一轮迭代，最小化人工介入；(5) 主动服务能力——基于手机通知主动识别用户需求。
- **值得关注的原因**:
  - **SOTA 性能**：MobileWorld 82.1%，MobileWorld-Real 92.2%，AndroidDaily 97.5%（移动端全面领先）；OSWorld-Verified 79.5%，WebArena 73.6%（桌面/网页端与国际顶级模型竞争）。直接对标 Opus 4.8、Gemini 3.1 Pro、GPT-5.6 Sol。
  - **Agent 工程化的标杆**：从真实设备环境 → 在线 RL → AutoResearch 自动迭代 → 主动服务，这是一套完整的 Agent 能力获取流水线。特别值得注意的是 100+ 步 RL 训练对长时程规划的提升。
  - **对 Agent 研究的启示**：论文也坦诚展示了失败案例（如朋友圈权限设置无法完成），说明即使 SOTA 模型在真实复杂任务中距离可靠仍有距离。这些失败模式本身就是很好的研究选题。
- **技术启发**: GUI Agent 正在从"能点"走向"能生活"。对于做 Agent 的同学，Qwen-UI-Agent 的数据飞轮思路——让 Agent 自己生成训练数据、诊断自己的失败——是一个可复用的范式，不限于 GUI 场景。

- **链接**: [arXiv:2607.28227](https://arxiv.org/abs/2607.28227) | [项目页](https://tongyi-mai.github.io/Qwen-UI-Agent/)

## 4. 💾 Metis: 记忆基础模型——把记忆从"外挂"变成"原生能力"

- **来源**: MemTensor (上海) + 人大 + NUS + 上交 + 同济, arXiv:2607.26760, HuggingFace 7/31 热门
- **作者**: Zeyu Zhang, Ziliang Guo, Yihang Sun 等 (MemTensor 团队, 合作 Tat-Seng Chua / NUS)
- **发生了什么**: 提出 **Memory Foundation Model** 概念——首次将长期记忆能力内化到基础模型的架构中。核心设计：(1) **Native Memory State**——在 backbone 内维护一个持久化、随推理动态演化的记忆状态；(2) **Memory Attention**——通过专门的注意力机制访问压缩的历史信息；(3) 在线记忆维护**无需梯度**，仅需一次前向传播即可更新；(4) 推理时模型权重完全冻结，记忆状态通过标准前向计算自主演化。
- **值得关注的原因**:
  - **范式转变**：当前几乎所有 Agent 记忆方案（MemGPT、MemoryBank、RAG）都是外挂式，记忆和推理分离训练、分阶段处理。Metis 通过 mid-training 将记忆能力内化，支持端到端优化，理论上记忆内容可以与推理任务更好地对齐。
  - **Agent 记忆基建的升级**：对于需要跨会话保持上下文的 Agent（如个人助理、研究 Agent），外部记忆的脆弱性（检索不准确、token 消耗大、安全投毒风险）一直是个瓶颈。Metis 的 Native Memory 路线提供了另一种可能。
  - **已开源**：模型权重和代码均已发布在 HuggingFace / GitHub，可以复现和进一步研究。
- **技术启发**: Agent 记忆的正交方案值得关注——是继续优化 RAG pipeline（检索质量、记忆压缩）、还是彻底内化记忆能力？两条路线的 trade-off（flexibility vs efficiency vs interpretability）是一个有深度的研究课题。对于做视频 Agent 的场景，视频信息的长期记忆（时序关联、事件检索）尤其需要这种基建升级。

- **链接**: [arXiv:2607.26760](https://arxiv.org/abs/2607.26760) | [GitHub](https://github.com/MemTensor/Metis) | [HuggingFace](https://huggingface.co/collections/IAAR-Shanghai/metis)

## 5. 📁 文件系统记忆的实证研究：组织、演化与可持续性

- **来源**: arXiv:2607.26637, 2026-07-28
- **发生了什么**: 首篇系统研究 **LLM Agent 文件系统记忆**（即以 Markdown 文件树形式维护长期记忆）的论文。将记忆角色抽象为三种 Agent：管理 Agent（整合组织新信息）、搜索 Agent（带引源的查询）、执行 Agent（将任务轨迹蒸馏为技能）。在不同记忆形态（Agent 组织的层级 vs 逐字 dump vs chunk 检索）、不同规模和工具集下，追踪答案质量、成本和存储健康度。
- **值得关注的原因**:
  - **务实且可操作**：很多 Agent 系统实际就是用文件系统做记忆的（MemGPT、大多数开源 Agent 框架），但之前没人系统研究过这种"默认方案"到底有多好/多差。论文发现：有组织的存储可将检索成本减半，但当前 Agent **无法将组织转化为更好的答案质量**；工具集的变化对存储形态的影响与模型切换相当——这个发现对"怎么设计 Agent 记忆系统"有直接的工程指导意义。
  - **记忆可靠性问题**：在持续增长场景中，除了最强的管理 Agent 外，所有 Agent 的组织能力都会衰减。这意味着长期部署的 Agent 面临"记忆腐烂"问题——对需要长期运行的视频监控 Agent、机器人记忆系统等领域，这是一个不可忽视的工程挑战。
- **技术启发**: 如果你在做需要长期记忆的视频/具身 Agent 系统，"文件系统记忆"是一个默认但远未解决的方案。要不要组织？怎么组织？组织成本值得吗？这篇论文给出的实证结论可以作为设计决策的参考基线。

- **链接**: [arXiv:2607.26637](https://arxiv.org/abs/2607.26637)
